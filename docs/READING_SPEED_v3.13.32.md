# The Viewer v3.13.32 PDF 읽기 속도 검증

측정일: 2026-10-07. 비교 소스: v3.13.31 → v3.13.32. 이전 RGB 전달·JPG 썸네일 개선 측정은 [v3.13.31 기록](READING_SPEED_v3.13.31.md)에 보존했습니다.

## 최종 적용본 측정

| 시험 문서 | 프로세스 시작 → 쪽수 수신 | 프로세스 시작 → 첫 이미지 수신 | 이미 열린 문서의 다음 쪽 |
| --- | ---: | ---: | ---: |
| 첨부 표 문서, 3쪽 | 463.3 → 47.1ms | 560.0 → 118.2ms | 19.3 → 17.5ms |
| 사진을 배치한 시험 PDF, 8쪽 | 468.1 → 46.5ms | 745.2 → 310.1ms | 188.6 → 204.4ms |
| 벡터 시험 문서, 200쪽 | 490.3 → 44.5ms | 610.9 → 125.6ms | 21.1 → 16.8ms |

각 값은 버전별 **5회 중앙값**입니다. 첨부 PDF의 첫 이미지 수신은 약 **560ms → 118ms**, 약 **4.7배** 빨라졌습니다. 사진 시험 PDF의 후속 쪽은 이번 측정에서 약 16ms 느렸으며, 후속 페이지 전체에 대한 속도 개선은 확인하지 않았습니다. JPG 최초 해독 엔진은 이번 변경의 대상이 아닙니다.

앞서 안내한 **581ms → 61ms는 최소 시제품**의 측정입니다. 최종 적용본은 원본의 정확한 페이지 좌표를 읽고 양식 표시의 호환 경로를 보강했으므로, 최종 수치를 61ms로 안내하지 않습니다.

## 범위와 조건

- 실제 GUI의 `worker_launch('--pdf-worker')` 호출, 작업 프로세스 시작, 쪽수 검사, 첫 쪽 RGB 데이터 전체 수신까지 측정했습니다. PY 실행용 작은 진입점의 최초 생성 시간도 포함합니다.
- 프로그램 주 창 자체의 시작 시간과 화면에 그리는 시간은 제외합니다. Windows EXE 시작 속도와 사용자의 PC에서 동일한 시간이 나오는지는 확인하지 않았습니다.
- Linux x64, Python 3.12.14, PySide6/Qt 6.11.1, pypdfium2 5.14.0, pypdf 6.10.0, Pillow 12.2.0에서 두 버전을 비교했습니다. 패키징에 고정한 주요 라이브러리 버전과 같습니다.
- 첫 이미지와 다음 이미지는 긴 변 1800px입니다. 세 문서에서 쪽수·출력 크기·첫 두 페이지의 RGB SHA-256이 모든 반복에서 기존 버전과 일치했습니다.
- 로컬 파일과 운영체제의 기존 디스크 캐시를 사용했습니다. 파일별로 두 버전의 실행 순서를 교대로 바꿨으며, 다른 성능 시험과 동시에 실행하지 않았습니다.
- 첨부 문서는 133,660바이트, 사진 시험 PDF는 13,231,794바이트입니다. 사진 시험 문서는 같은 사진을 재사용한 합성 8쪽 문서이며, 모든 스캔 PDF를 대표하지 않습니다.

## 반영 내용

1. 읽기 작업 프로세스의 진입점을 GUI와 PDF 편집 모듈 초기화보다 앞에 두었습니다. PY 실행에서는 작은 전용 진입점을 생성해 프로그램 전체 소스를 다시 해석하는 비용을 줄이고, 설치 EXE는 이미 컴파일된 빠른 진입점을 사용합니다.
2. PDFium이 원본 파일을 직접 읽습니다. 읽기 화면에서는 편집용 문서 복사·PDF 재저장과 Pillow 픽셀 변환을 생략합니다. RGB 전달 방식과 기존 화면 해상도는 유지합니다.
3. 소수점 CropBox·MediaBox, 회전과 UserUnit의 정확한 좌표는 pypdf에서 읽습니다. PDFium의 단정도 페이지 크기만 사용했을 때 나타났던 표선의 픽셀 차이를 방지합니다.
4. 양식 또는 위젯 주석이 있는 페이지와 편집·변환 등의 요청은 같은 프로세스에서 기존 코드로 이어집니다. 전환을 일으킨 요청은 한 번 처리하며, 호환 처리 후 일반 읽기는 다시 빠른 경로를 사용합니다.
5. 원본이 바뀌면 읽기 문서를 다시 엽니다. 읽기 문서는 최대 4개, RGB 한 화면은 최대 75MB로 제한하고, 편집·종료·해제 요청에서 파일 핸들을 닫습니다. 임시 읽기 진입점을 만들 수 없으면 기존 PY 실행 경로를 사용합니다.
6. 패키징 PY v1.5.8과 GitHub 업데이트 PY v2.1.1은 이 뷰어에 pypdfium2 5.14.0을 사용합니다. GitHub 도구가 이전 5.3.0 의존성을 다시 넣는 문제도 수정했습니다.

## 검증 근거

- 읽기·프로토콜·캐시·JPG·ZIP·듀얼 보기와 표 편집·저장 관련 **80개 시험이 통과**했습니다. 표선·한글 글자 혼합 이동, 다른 쪽 같은 좌표 붙여넣기, 편집 직후 Ctrl+S와 저장 PDF 재열기를 포함합니다.
- 회전 4방향, 잘라낸 페이지, 소수점 좌표, UserUnit, 투명도·일반 주석 및 양식 호환 화면을 기존 엔진과 픽셀 단위로 비교했습니다.
- 패키징 소스 인식과 내장 파일 10개 검사를 통과했습니다. 실행 검사는 **21개 항목 완료, 19개 통과, 2개 해당 없음**입니다. 이 Linux 환경에서 Windows Shell과 미동봉 Office 엔진 검사는 해당 없음으로 기록했습니다.
- 패키징 실행 검사에 PNG 응답의 기존 호환성, 빠른 RGB 응답, 양식 호환 응답과 기존 엔진 대비 픽셀 일치 검사를 포함했습니다.
- GitHub 업데이트 도구의 **23개 로컬 시험이 통과**했습니다. 최신 소스의 PDFium 버전 선택, Markdown 본문·폴더 보존과 간편 업로드 화면을 확인했습니다. 원격 전송 단계는 테스트 대역으로 검사했습니다.
- Windows EXE의 빌드·설치와 GitHub 원격 업로드는 수행하지 않았습니다. Windows 빌드에서는 기존의 소스 및 완성 EXE 기능 검사를 계속 수행해야 합니다.
