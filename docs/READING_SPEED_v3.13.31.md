## 조건과 범위

- Linux, Python 3.12.14, PySide6 6.8.3, Qt offscreen, 1200×820 시험 창, 로컬 파일.
- 같은 JPG 시험 파일 10,580,801바이트와 그 JPG를 배치한 8쪽 PDF 13,231,794바이트를 사용했습니다. 일반 문서 전체를 대표하는 표본은 아닙니다.
- PDF 화면의 긴 변은 1800px, JPG 최초 해독은 최대 1024×1024px, 썸네일은 최대 280×370px입니다.
- PDF 첫 화면은 새 읽기 프로세스 시작부터 화면 수신까지입니다. 운영체제의 디스크 캐시를 비우지 않아 디스크의 완전한 최초 읽기 시간은 아닙니다.
- JPG 해독·썸네일 값은 원본 해독기 함수의 시간이고, 이전 쪽 이동은 실제 창의 이동 요청부터 표시 완료까지입니다.
- Windows 설치 EXE 및 사용자의 PC에서 같은 성능이 나오는지는 확인하지 않았습니다. 파일 내용·해상도·저장장치·PC에 따라 시간이 달라집니다.

## 수정 내용

1. PDF 화면 전달에서 PNG 압축·Base64 변환·PNG 해제를 제거하고 RGB 픽셀을 전달합니다. PDF 렌더링 엔진과 렌더링 해상도는 유지합니다.
2. 주 보기 또는 미리 읽기로 얻은 화면에서 썸네일을 만들고, 같은 쪽의 대기 중인 썸네일 읽기를 제거합니다. 작은 원본을 확대해 썸네일을 만들지 않습니다.
3. 이미지 해독기 안에서도 이미 읽은 큰 화면으로 작은 썸네일을 만들 수 있습니다. 원본 재검사는 캐시를 사용하기 전에 수행합니다.
4. 최근 페이지 캐시를 최대 8쪽·64MiB로 제한하면서 앞뒤 이동에 재사용합니다. 부족한 해상도로 확대 화면을 대신하지 않습니다.
5. PDF의 진행 중인 다음 장 미리 읽기 결과도 주 보기에서 이어받습니다.

- 나뉘어 들어오는 데이터 수신, RGB 데이터 내부 줄바꿈, 잘못된 행 길이 거부, 뒤따르는 PDF 쪽수 응답을 점검했습니다.
- JPG 방향 보정, 원본 변경 시 캐시 거부, 확대 시 큰 해상도 재읽기를 점검했습니다.
- 두 자료·ZIP의 미리 읽기, 캐시의 메모리 제한, 이동 중 오래된 응답 거부와 원본·수정본 구분을 점검했습니다.
